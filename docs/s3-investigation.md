# S3 睡眠排查：为什么这块主板睡不了

> 结论先行：**PCH 能进入 S3（CPU 停止），但主板没有把 `SLP_S3#` 接入 VRM/电源使能，主供电不断，平台卡在半睡状态。这是板级硬件设计的省略，ACPI 表与固件都无法修复。**

## 1. 现象

原厂固件两份 DSDT（`C118F50D` 大表 / `1B852CE9` 小表）**都没有 `_S3` 对象**，因此 Windows 的 `powercfg -a` 里根本没有“待机 (S3)”，开始菜单也没有睡眠按钮。

手动补上 `_S3` 后，Windows 能识别 S3，但点击睡眠会出现两种失败：

| `_S3` 包的值 | 现象 | 事件日志 |
|---|---|---|
| `0x05`（原厂/七彩虹同款值） | 直接断电，风扇停、灯灭 | 无 42、无 107；41 + 6008 |
| `0x03` | **不断电**，风扇转、灯亮、网络断开，卡住 | 无 42、无 107 |
| 大表（含 `_PTS` 分支 + `Notify(PWRB)`） | 同上 | 同上 |

关键点：**没有任何一次成功记录 42（进入睡眠）或 107（恢复）**。

## 2. 排查过的假设

| 假设 | 验证方式 | 结果 |
|---|---|---|
| DSDT 缺 `_S3` | 反编译两份 DSDT | 确实缺，已补 |
| `SLP_TYP` 值错 | 分别刷 `0x03` 与 `0x05` | 都不是答案 |
| 固件缺 S3 模块 | 模块清单比对 | `S3Save`、`S3Resume`、`CpuS3Pei`、`AcpiS3SaveDxe`、`PchS3Peim` **全部存在**，大小与七彩虹一致 |
| `SleepSmi`（SMM）缺代码 | 逐字节比对 `.text` | 两边 99% 一致；本机反而**多** 96 字节，差异位于数据表区域而非函数 |
| 七彩虹存在“拦截 0x05 并改写为 S3” | 反汇编 `SleepSmi`，搜索 EC 端口 0x62/0x66 | **不存在**，两边都没有 EC 通信指令 |
| 两份 DSDT 的用途 | 改 `OS Selection` 后 dump | `Windows 8.X` → 大表；`Windows 7` → 小表 |
| 隐藏选项 `S3 Video Repost` | AMIBCP 遍历全部菜单 | 字符串存在但未挂到任何菜单，无法开启 |
| 复位缺陷导致 S3 失败 | 修好热复位后再测 | 无关，S3 依旧失败 |
| 硬件省料 | 设备枚举 | 双网口、6×SATA、声卡、4×PCIe 根端口齐全，不是丐版 |

## 3. 关键推理

进入 S3 的流程是：

```
Windows 读 \_S3 → 执行 _PTS(3) → 往 PM1_CNT 写 SLP_TYP + SLP_EN
                                    ↓
                              PCH 硬件执行，固件不参与
```

`_PTS` 里该做的都做了（`PPTS` 会设置 `G1S3/G1S2/G0S` 等 GPE 使能位），`SLP_TYP` 的两个候选值也都试过。

现象说明：

- **`0x05`**：PCH 按 S5 处理 → 拉低 PS_ON → 整机断电；
- **`0x03`**：PCH 按 S3 处理 → **CPU 停止（网络断开）**，但风扇仍转、电源灯亮 → **主供电没有被切断**。

结论：`SLP_S3#` 这根 PCH 睡眠信号没有参与板级供电控制。正规设计里它要送到 CPU 供电使能（关断）与内存供电使能（保持）；这块板只把 PS_ON（S5）接到了电源。

## 4. 社区佐证

蜗牛星际 B 款双网口玩家普遍不使用系统睡眠，而是用：

- 硬盘休眠（HDD spin-down）
- WOL 网络唤醒
- BIOS RTC 定时开关机

没有公开记录显示该型号的 S3 可用。

## 5. 建议

- 使用 **S4 休眠**（`powercfg /h on`）；
- Windows 中隐藏“睡眠”按钮，避免误触卡死；
- NAS 场景使用硬盘休眠 + WOL。

## 6. 如果仍想验证

在“卡住、风扇仍转”的状态下，用万用表测量 **ATX 24pin 的 PS_ON（绿线）**：

- 仍为高电平 → 电源未被关断，印证 `SLP_S3#` 未参与板级供电；
- 变为低电平 → 电源被关断，属于另一种失败模式。

这一测不需要拆机，也不需要接触 128 脚芯片。
