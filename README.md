## 一、这个仓库解决什么问题

这块主板有一个出厂就存在的缺陷：

**在 Windows 启动管理器（F8 菜单）、WinRE 或 PE 里按 `Ctrl+Alt+Del`，机器会黑屏并无限重启，只能拔掉电源才能恢复。**

冷启动（关机再开机）完全正常，所以平时不容易发现；一旦系统更新、进恢复环境或误按，就会被卡死。

本仓库提供：

- 一份**只修复该缺陷**的完整固件（保持原厂 DSDT，不引入其它改动）；
- 修改后的 `PchReset` 模块（可单独复用）；
- 根因分析与字节级补丁说明；
- 另一项排查（S3 睡眠）的完整结论：**该主板硬件未设计 S3，软件无法修复**。

| S3 睡眠 | ❌ 硬件未设计，无法修复 |

## 二、根因

热复位最终由 DXE 驱动 `PchReset`（GUID `F5883FC5-F8EE-4E44-B386-6021FB320C9B`）执行：

```asm
mov dx, 0CF9h
mov al, 2
out dx, al        ; CPU 复位
mov al, 6
out dx, al        ; 系统复位 —— 本平台忽略该值，复位未发生
while (1) ;       ; CPU 在此死转 → 看门狗复位 → 无限循环
```

本平台（Bay Trail-D）的 `0xCF9` 需要写入 **`0x0E`（全复位，含 ME）** 才会真正复位；`0x06` 被忽略，于是 CPU 卡在后面的死循环里。

对比同平台的七彩虹 C.Q1900M 固件（同 GUID 模块 6240 字节，本机 2848 字节），其复位路径会先写 `0xFED03048` 的 bit14（全局复位使能）再复位；本机没有这段，且只用 `0x06`。

---

## 三、修复内容（字节级）

对 `PchReset` 模块（PE32+ x86-64，DXE 驱动）做 3 处修改：

| 模块内偏移 | 原值 | 新值 | 作用 |
|---|---|---|---|
| `0x7FF` | `B0 06` | `B0 0E` | 复位值 0x06 → 0x0E（全复位） |
| `0x851` | `B0 06` | `B0 0E` | 同上（第二处复位调用） |
| `0x7F1`–`0x7F5` | `E8 9E FE FF FF` | `90 90 90 90 90` | 跳过胶囊更新专用路径 `sub_694`（本机不存在 `CapsuleUpdateData` 变量） |

模块大小不变（2848 字节），PE 头、校验和结构完整。

## 六、刷写方法（风险自负）

1. 准备 FAT32 U 盘，放入 `AfuEfix64.efi` 与 `final_2026-11-06_noS3.rom`；
2. U 盘根目录建 `EFI\BOOT\BOOTX64.EFI`（UEFI Shell），开机按 F11 选择该 U 盘；
3. 在 Shell 中执行：

```
AfuEfix64.efi final_2026-11-06_noS3.rom /P /B /N /X
```

4. 刷完自动重启；进入 BIOS 重新设置时间、启动项（刷写会重置 BIOS 设置）。

> ⚠️ 刷写过程中**严禁断电**。刷写失败/变砖只能靠 CH341A 等编程器夹 SPI Flash 恢复。

## 八、关于 S3 睡眠

本主板 **S3 睡眠不可用，且无法通过软件修复**。

我们做过完整排查（补齐 `_S3`、试 `0x03`/`0x05` 两种 SLP_TYP、比对全部 S3 相关固件模块、反汇编 `SleepSmi`、搜索隐藏 BIOS 选项），结论是：

- PCH 能接受 S3 命令（CPU 停止、网络断开），但主板**没有把 `SLP_S3#` 接入 VRM/电源使能**，主供电不切断，平台卡在“半睡”状态；
- 这是**板级硬件设计**的省略，ACPI 表与固件都补不了。

详细过程见 [`docs/s3-investigation.md`](docs/s3-investigation.md)。

省电建议：使用 **S4 休眠**、硬盘休眠、WOL 与定时开关机。
